## What the code actually shows

### 1. `WRONG_FORM` does not establish that the room belongs to another form

In `artifacts/api-server/src/ujs/calendar_protocol.py`, `validate_unfiltered_room_and_schedule()` contains this check:

```javascript
const control = label.control;
if (!control || control.form !== form)
  return {control: controlName, reason: "WRONG_FORM"};
```

That combines two different failures:

- The label has no associated control.
- A control exists, but belongs to a different form.

Consequently, the earlier explanation—“the room control was associated with a different form”—was stronger than the diagnostic justified. The agent’s latest correction is accurate. That inconsistency is a plausible explanation for why the new path fails where the existing room-discovery approach can succeed—but it is not proof of the live cause.
