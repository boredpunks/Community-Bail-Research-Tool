The Replit app is stuck on bugs in its own code, not on the court website. The office dropdown problem from the last three inspections is a one-line code bug, and I have the fix ready on a local branch.

## What I found

**The 49 choices.** I opened the court portal's search page once, chose Date Filed, ticked Advanced Search and selected Allegheny. I didn't click Search or download anything. The office dropdown has 49 entries: one blank, plus 48 local criminal-court (MDJ) offices. They display like this:

`MDJ-05-2-01-Smith, Tara` … `MDJ-05-3-17-Kearney, Jack`

Each one shows the office code and then the judge's name. The code lines up with docket numbers: office 05-3-17 matches dockets like `MJ-05317-CR-…`, which I saw on October 5.

**The bug.** The code that reads each option (`filing_inventory.py`, line 191) only accepts a code if a space, a closing bracket or the end of the text comes right after it. On the real site a hyphen comes next ("05-2-01-Smith"), so all 48 offices fail. The tests passed anyway because none of the made-up test options used the real format.

I checked this by running the app's actual pattern in Node against the real labels:

| Input | Current pattern | Fixed pattern |
|---|---|---|
| `MDJ-05-2-01-Smith, Tara` | no match | `MDJ-05-2-01` |
| `05-2-99-CR-…` (looks like a docket number, should be rejected) | rejected | still rejected |
| The existing test cases | match | same results |

**The fix** lets a hyphen follow the code as long as a name comes after it. It still rejects text that continues into a docket number (`-CR-`, `-MD-` and so on). It's 3 lines on a local branch, `fix/mdj-office-label-hyphen`: 1 line in the code and 2 lines adding a test option in the real format. I haven't run the app's Python test suite, because Playwright isn't installed here. I also left the method version at v7, because moving to v8 means changing how the app reads old v7 reports, which is Replit's job.
