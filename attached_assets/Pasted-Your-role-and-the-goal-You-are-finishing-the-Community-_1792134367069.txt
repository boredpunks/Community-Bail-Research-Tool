The project helps community volunteers find public Allegheny County criminal dockets with a low stated monetary bail. Volunteers can then verify each one by hand. It reads the public UJS portal (https://ujsportal.pacourts.us/CaseSearch) and docket sheet PDFs.

What the inspection found (verify each item before you change code)
1. The October 12 failure was the app's own navigation timeout, not the court
The evidence is the request log in docs/court-access-pilot-results.md for permit a7734b57-…, job b25c9b18-…:

Request	Completed (UTC)
GET /resource/js/sitemain.min.js	13:17:36.358
POST /CaseSearch (Search)	13:19:00.103, HTTP 200
GET /resource/css/sitemain.min.css (result page re-requests it)	13:20:09.604
Job ends	13:20:37.839
Here is how the code produces that pattern:

submit_calendar_search (src/ujs/calendar_protocol.py, around line 229) wraps the Search click in page.expect_navigation(wait_until="load", timeout=SEARCH_CLICK_TIMEOUT_MS). SEARCH_CLICK_TIMEOUT_MS = 180_000.

Every routed request, including each CSS or JS file the result page re-requests, waits 60–90 seconds first (random.uniform(60, 90) in worker.py, around line 98). The results page can't fire load until both of its asset files arrive. That means about 80 seconds of waiting before the POST, about 69 seconds before the CSS, then another 60–90 seconds before the JS.

The timer started at the click, about 13:17:36. 180 seconds later is about 13:20:36, which is when the job ended, before the JS file was requested.

Playwright then throws TimeoutError, which is not a RuntimeError. The handler in worker.py (around lines 440–472) emits calendar_state=RESULTS_NOT_VALIDATED, because the POST had completed. It then turns the code into UNEXPECTED_RESPONSE, because "TimeoutError" isn't on the safe-code allowlist.

The worker's barrier message then calls validationStop("SOURCE_VALIDATION_BARRIER") (src/lib/discovery-worker.ts, around line 256). That sets the source-wide stop.

So the result page was probably never parsed. The parser in evidence.py may be fine for Common Pleas results; it just wasn't reached.

Treat this as a strong hypothesis and confirm it offline (task 2) before you rely on it.

2. Who set SOURCE_VALIDATION_BARRIER
The worker's barrier message from that failed run set it automatically. validationStop also clears accessVerifiedAt, verifiedMethod and collectionApprovedAt. Nobody set it by hand, and it doesn't mean the court refused access. Clearing it is an operator decision (task 6).

3. The office dropdown bug (fix is ready)
On Oct 16 I opened the portal page once, chose Date Filed, ticked Advanced Search and selected Allegheny. I did not click Search. The "MDJS Court Office" dropdown then listed 49 entries: one blank and 48 offices. Every office label puts a hyphen between the code and the judge's name, for example MDJ-05-2-01-Smith, Tara and MDJ-05-3-17-Kearney, Jack.

The regex in src/ujs/filing_inventory.py (around line 191) ends with the lookahead (?=$|[\s)\],;:]). That lookahead rejects a hyphen, so none of the 48 offices are recognized. The tests passed only because no fixture used the real format.

The fix changes the lookahead to:

text
(?=$|[\s)\],;:]|-(?!(?:CR|MD|TR|NT|SU|LT|CV)-)[A-Za-z])
This accepts a hyphen followed by a name and still rejects docket-like suffixes such as 05-2-99-CR-…. It's in commit 519e5aa on branch fix/mdj-office-label-hyphen, and also as a patch file. The commit also adds one fixture option, MDJ-05-2-90-PRIVATE_NAME_SENTINEL, Fixture, with expected output {'code': '05-2-90', 'kind': 'EXPLICIT_MDJ', 'enabled': True, 'selected': False}.

I checked the fixed pattern in Node against the real labels and the existing fixture cases. The Python suite was not run. The method string was left at v7 on purpose (see task 4).

4. Other blockers I found
Fixed date that is already past. calendarPreviewCriteria in src/lib/discovery-safety.ts, the POST /discovery/calendar-previews route (eventDate !== "2026-10-15") and the OpenAPI enum eventDate: ["2026-10-15"] all hardcode a date that has already passed. As a result, pilot prepare-calendar-only can never succeed again.

Fixed court office. OpenAPI (courtOffice: enum [CP-05-02-Crim]) and pages/discovery.tsx (lines 226, 250, 387) hardcode the Common Pleas office. The page's court and event dropdowns use onChange={() => undefined}, so the user can't choose anything.

Results parser only handles Common Pleas. evidence.py matches dockets with DOCKET = CP-02-CR-\d{7}-\d{4}, accepts only /Report/CpDocketSheet links, and requires County = Allegheny and Court Office equal to the criteria value. MDJ dockets look like MJ-05xxx-CR-0000000-YYYY and link to /Report/MdjDocketSheet?docketNumber=…&dnh=…, which I saw on October 5 filing-date results. The office code maps to the docket prefix: MDJ-05-3-17 ↔ MJ-05317-….

Live form inspection is switched off. formInspectionLiveEnabled = false in src/lib/form-inspection.ts. The HTTPS relay and network-sandbox work (inspection-fetch-broker.ts, network_sandbox.py) only serves that switched-off 3-request check.

Definition of done
The project is finished when all of these are true, each backed by real output:

A volunteer can pick the search method in the UI, without editing code:

(a) a Calendar Event search for Bail Hearing;

(b) a Calendar Event search for Preliminary Arraignment;

(c) a criminal filing-date search by MDJ office.

The court office, any future date window allowed by the source and the bail limit are also chosen in the UI. Nothing is substituted silently.

One live search of each method you support returns a validated result set, or a validated empty result. Each method's state is recorded in the docs as working, failing (with the exact error code) or not yet tried.

The worker downloads docket PDFs for result rows one at a time, at the approved spacing. It extracts the docket number and stated bail, excludes bail shown as posted, and stops at the first HTTP 429 or 403.

A human has compared the first 3 extracted PDFs with the app's output, field by field, and the comparison is recorded.

The volunteer report shows only the docket number, the stated bail amount and type, whether bail is shown as posted, and custody stated as "not established by this source." Each row links to its source docket sheet and carries the required statement.

The typecheck, build and safety test suite pass, and the real output is pasted into the docs.
