Neither promise is awaited, returned, cancelled, or otherwise accounted for.

Immediately afterward, the test creates the actual controlled pair:

```ts
const concurrentGets = [
```

Therefore, the test starts four reservation operations while observing and awaiting only two of them. The first two operations can continue asynchronously, contend for the same source lock, enter scheduler wait loops, consume a reservation, or reject after test teardown. That can make the safety run nondeterministic and can invalidate the intended assertion that exactly one of the two controlled operations receives a grant.

The production scheduler already serializes admission through a source row lock, checks the persisted in-flight request, waits outside the transaction, re-enters the transaction, and rejects a repeated bounded-engine bootstrap path after it has already been attempted. Preserve that behavior unless runtime evidence establishes a separate production defect.

ROOT CAUSE

This is a test-lifecycle defect, not currently an established production scheduler defect.

The concurrency test creates two unused reservation promises:

```ts
const firstConcurrentPath = boundedPath("/CaseSearch");
const secondConcurrentPath = boundedPath("/CaseSearch");
```

It then creates a second pair for the same path and awaits only that second pair. Calling an async function starts execution immediately; assigning its promise without awaiting it does not make it inert.

The two orphaned operations may:
- Acquire the source slot before the intended operations.
- Add unexpected request rows.
- Change `requestsUsed`.
- Enter a polling loop.
- Reject after the disposable schema or connection pool is removed.
- Cause an unhandled rejection.
- Make `Promise.race(concurrentGets)` observe behavior influenced by requests outside `concurrentGets`.

Remove the two orphaned calls completely.

Delete:

```ts
const firstConcurrentPath = boundedPath("/CaseSearch");
const secondConcurrentPath = boundedPath("/CaseSearch");
```
