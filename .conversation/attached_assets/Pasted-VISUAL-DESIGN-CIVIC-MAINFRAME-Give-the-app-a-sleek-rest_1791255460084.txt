VISUAL DESIGN — “CIVIC MAINFRAME”

Give the app a sleek, restrained 1990s hacker-terminal aesthetic.
This is a playful visual treatment for a serious public-record
research tool.

Keep the previously specified accuracy, privacy, source-access,
and verification requirements unchanged.

DESIGN TOKENS

Background: #080D0A
Panel background: #101A14
Primary text: #C8F5D5
Accent green: #65FF91
Secondary text: #A2B8A8
Borders: #304C3A
Warning accent: #FFD166
Error accent: #FF9292

Use these as starting colors; check actual text/background
contrast before finalizing.

TYPOGRAPHY

Use a monospace stack for the title, labels, docket numbers,
and amounts.

Use highly readable text for explanations and evidence.
Default body text to approximately 18px.
Never shrink critical details to achieve the aesthetic.

LAYOUT

Header:
ALLEGHENY BAIL SEARCH_
Public-record research terminal

Main area:
- One prominent search field
- Optional filters under “Refine search”
- A clearly labeled SEARCH RECORDS button
- Results immediately below
- Expandable source and evidence details

Keep buttons large, labels explicit, and navigation shallow.
Avoid icon-only controls.

RESULTS

Use a clean table with generous row spacing.
Right-align monetary amounts.
Keep docket numbers easy to select and copy.

Use plain-English status labels:
- Custody confirmed as of [date/time]
- Custody unknown
- Older custody evidence
- Needs review
- Source unavailable

Do not communicate status through color alone.
Do not make unknown or unverified records look approved.

On smaller screens, use readable stacked result cards rather
than compressing the table into tiny text.

TERMINAL DETAILS

Use restrained details:
- A thin green rule below the header
- Subtle glow on the app title only
- Small bracket-style section labels
- Optional static cursor beside the title
- A faint grid in empty background areas, not behind text

No animated code rain.
No flashing effects.
No typing animation that delays results.
No sound effects.
No fake loading messages or fake progress indicators.
No “police database,” “classified,” or “government authorized”
branding.

SEARCH FEEDBACK

Show only real activity:

“Checking selected sources…”
“Reviewing imported records…”
“Search paused: source request limit reached.”
“Partial results: one source was unavailable.”

Never use fictional phrases such as:
“Bypassing firewall”
“Cracking database”
“Access granted”

ACCESSIBILITY AND COMFORT

Provide an obvious “Standard view” toggle that switches to a
plain light theme without changing functionality.

Support browser zoom, keyboard navigation, visible focus,
screen readers, and reduced-motion preferences.

The hacker theme must never reduce readability or obscure
warnings, sources, timestamps, or uncertainty.

DESIGN GOAL

The user should feel like a movie hacker while doing ordinary,
clearly explained research—not need technical knowledge to
operate the app.
