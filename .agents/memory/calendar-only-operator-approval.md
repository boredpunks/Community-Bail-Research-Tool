---
name: Calendar-only operator approval
description: Approval boundaries for narrow source checks while regular collection remains blocked.
---

A user-approved one-use calendar gate is separate from general source access and collection approval. Approval to build it is not approval to run it.

The user's later functional-engine authorization supersedes earlier
observation-only scope: supported scoped permits may cover calendar submission,
validated docket documents, extraction and pending storage. After a successful
stage, create a fresh permit and continue without another conversational approval.
After a consumed failed live attempt, diagnose offline and obtain fresh approval
before another source attempt.

During the completion effort, implement authorized routine offline repairs,
tests, builds and integration without another review/proposal or permission
loop. Once those prerequisites pass, execute within a current exact live
authorization using the existing controls. If a mandatory gate needs the user's
interaction, present that exact gate, not a proposal to prepare it.

**Why:** The user explicitly said “End the planning loop. Execute the authorized
work” after repeated reviews/follow-up proposals, and clarified that the goal is
live calendar-to-docket-to-bail retrieval, not diagnostics alone.

**How to apply:** Deliver integrated verified work and actual results or a
demonstrated blocker. Preserve all method/date/budget/permit and source-stop
boundaries. Never convert a failed consumed run or unused budget into retry
authority; routine offline work needs no repeated approval within this scope.

**Why:** The user explicitly authorized execution of the complete bounded engine,
not repeated proposals, while forbidding global barrier removal and automatic
retries.

**How to apply:** Preserve historical permits, source-wide stops and method-specific
proof boundaries. An integrated pilot that clears the global barrier is not an
acceptable substitute for a scoped engine permit that leaves it unchanged. Keep
the selected scope and aggregate ceilings explicit; stricter operator limits win.

**Why:** The user approved a separate one-use operator gate only for the selected calendar search, with regular collection blocked and PDFs disabled.

**How to apply:** Obtain fresh execution approval for the exact scope. Preserve the source-wide barrier, stop without retries on failed validation or denial, and do not treat calendar results as PDF access proof or bail evidence.

Keep the exceptional gate operator-only rather than exposing it to every shared-password web session.

**Why:** The shared workspace login does not distinguish an operator from other workspace users. The existing operator CLI preserves that boundary without creating a broader web permission.

**How to apply:** Use the operator flow for exceptional checks unless the user separately requests and approves a role model. Ordinary web collection stays blocked.
