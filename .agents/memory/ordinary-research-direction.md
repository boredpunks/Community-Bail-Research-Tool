---
name: Ordinary user-driven research
description: The current user direction supersedes pilot-only approval and fixed-scope restrictions for ordinary authenticated research.
---

Ordinary authenticated calendar searches must not require per-run operator
approval or single-use permits unless an actual applicable external
requirement mandates them. Do not extend the pilot framework. Optional office,
room and event filters replace the fixed Courtroom 506/Bail Hearing scope.

**Why:** The user explicitly said “Stop extending the pilot approval framework”
and directed a usable user-driven calendar-to-docket-to-bail workflow.

**How to apply:** Treat older operator/pilot notes as historical, not ordinary
product restrictions. Preserve authentication, real source evidence, genuine
denials, shared quotas, server waits and stop-on-challenge behavior. An
isolated constructed document-request failure is not evidence of a permanent
ban on unrelated calendar operations; require retained origin evidence when
scoping it.

Local PDF extraction, calendar discovery, document retrieval, filtering and
pending saving require independent acceptance. Manual source actions/uploads
are a supported fallback when automated document transport is unavailable,
but must not be labelled successful live retrieval.

**Why:** The user repeatedly corrected making independent stages wait on one
another and explicitly requested a working source-action/PDF-upload fallback.

**How to apply:** Finish authorized offline implementation and verification
without asking whether to begin it. Do not commit personal PDF records.

For the volunteer Bail Search, use the live calendar search. The later
three-screen simplification supersedes the collected-evidence alternate-mode UI.
Do not describe live
search as unavailable or “coming soon” when runtime readiness allows it; show the
actual date, scope, quota and pacing limits instead.

**Why:** The user said the live calendar-to-document search was already set up and
confirmed working, and corrected the collected-only form and “coming soon” copy.

**How to apply:** Route the ordinary volunteer form through the existing bounded
calendar workflow and preserve source admission, pacing, pause and uncertainty
safeguards. Do not issue real court requests just to test the interface.

The user-defined volunteer workflow has exactly three menu entries: Search,
Review, Candidates. Search is the existing live court search with very simple
settings, a Search button beneath them, and raw unfiltered results below the
button: row, docket, date, and bail amount when applicable. Launching a new
search resets the displayed Search and Review results. Matching results appear
immediately in Review, which contains only results from the last search with
docket number, bail amount, and a source-PDF citation link. Only results explicitly
marked “candidate” are saved under Candidates.

**Why:** The user corrected adding unnecessary tabs that obscured the existing
app and explicitly defined this simpler workflow.

**How to apply:** Simplify the existing screens rather than adding parallel
navigation or extra save-for-review steps. Keep automatic matching into Review
separate from explicit persistence into Candidates. A display reset is not
authorization to delete existing saved records.
Report live outcomes separately from local/browser-mocked checks. Pacing
defaults are not court requirements; preserve only stricter requirements
actually supported by policy or observed server instructions.

Do not make volunteer UI delivery depend on completion of a separate calendar
reliability task. Reuse proven extraction while reporting live calendar access
separately; a fixed-docket cached run is not general date-range discovery.

**Why:** The user explicitly requested building the volunteer UI on what is
proven and cancelling the separate reliability work.

**How to apply:** Use actual source admission rules, not task status, to decide
whether a submitted live search can run. Preserve partial results and explicit
resume behavior without claiming live verification from cached evidence.

For the volunteer onboarding release, show "Live calendar discovery coming soon —
currently searching X collected dockets" with a real distinct collected-docket
count. The volunteer form searches collected evidence only; this does not remove
the separate Advanced court search or relax its safeguards.

**Why:** The user explicitly added this notice to the publish-and-onboard step
after approving the volunteer UX proposal.

**How to apply:** Keep this release scope separate from older instructions about
ordinary advanced research. Do not enable live collection from the volunteer form
or substitute development counts for production evidence. Feedback is shared;
search results remain session-private until explicitly saved to the workspace.
